2. Consumo Asíncrono Dual: SQL (Supabase) & NoSQL (Firebase)

El sistema integra dos fuentes de persistencia desacopladas y complementarias, gestionadas mediante orquestación concurrente con RxJS forkJoin:

Base Relacional SQL: Supabase REST API

  • Entidad gestionada: Registros empresariales e inventario de activos.
  • URL Endpoint: https://cpgpvryfcmeedkgnprqs.supabase.co/rest/v1/
  • Mecanismo de consumo: Cliente SDK oficial @supabase/supabase-js con autenticación mediante apikey pública y validaciones asíncronas de unicidad para claves SKU.
  • Tolerancia a fallos: Mecanismo de fallback reactivo que preserva la operatividad offline y la réplica sincronizada.

Base NoSQL Orientada a Documentos: Firebase Firestore

  • Entidad gestionada: Bitácora y telemetría de eventos de auditoría (Audit Logs).
  • Project ID: gestion-nosql
  • Mecanismo de consumo: Subscripciones reactivas de flujo abierto onSnapshot conectadas a observables de RxJS.
  • Reactividad en tiempo real: Cada inserción o evento producido en cualquier cliente se sincroniza de forma inmediata sin recarga de pantalla.

3. Arquitectura Basada en Componentes Reutilizables (RA 3)

La aplicación sigue estrictamente el patrón arquitectónico MVVM / Standalone Components con detección de cambios optimizada mediante ChangeDetectionStrategy.OnPush y Angular Signals:

DataTableComponent (app-data-table)

Componente agnóstico e instanciable para visualización de colecciones tabuladas. Recibe @Input() data y @Input() columns, y notifica eventos al padre mediante @Output() rowAction. Incluye motor de búsqueda en tiempo real, ordenación multicriterio y paginador accesible.

MetricCardComponent (app-metric-card)

Widget estadístico de alto impacto visual para indicadores clave (KPIs). Admite valores, tendencias porcentuales, paletas cromáticas accesibles y emisión de eventos de pulsación.

ChartWidgetComponent (app-chart-widget)

Envoltorio declarativo sobre la librería Chart.js. Gestiona el ciclo de vida del canvas destruyendo adecuadamente las instancias en ngOnDestroy() para evitar fugas de memoria (memory leaks).

4. Cumplimiento Normativo WCAG 2.1 Nivel AA (RA 4)

La interfaz ha sido diseñada aplicando los principios fundamentales de accesibilidad web (Perceptible, Operable, Comprensible y Robusto):

  • Navegación completa por teclado: Todos los elementos interactivos cuentan con atributos tabindex lógicos y estilos de foco visibles de alto contraste mediante la pseudo-clase :focus-visible.
  • Contraste cromático reglamentario: Ratio de contraste superior a 4.5:1 en textos normales y 3:1 en tipografías grandes e iconos de control.
  • Etiquetas WAI-ARIA semánticas: Uso sistemático de role="table", role="region", role="alert", aria-live="polite" y descripciones aria-label en todos los componentes.
  • Diseño adaptativo Mobile-First: Maquetación con CSS Grid y Flexbox sin distorsión anatómica entre monitores de escritorio, tabletas y teléfonos inteligentes.

5. Protocolo de Auditoría Google Lighthouse (> 90/100)

Para verificar la puntuación exigida en el criterio de evaluación de la actividad (>90 en Accessibility y Best Practices):

  1. Abra la aplicación en el navegador Google Chrome.
  2. Abra las Herramientas de Desarrollador (pulsando F12 o Ctrl + Shift + I).
  3. Seleccione la pestaña Lighthouse.
  4. Marque las casillas Accessibility, Best Practices y SEO en modo Dispositivo Móvil o Desktop.
  5. Haga clic en Analyze page load para certificar la puntuación superior a 90/100.
